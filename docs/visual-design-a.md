# 中性浅灰工作台：ttkbootstrap 调整版

本轮统一主页、API 配置、人物候选、编辑选片组、检测/调整人脸框、AI 选片与导出六类页面。处理算法、API 请求、工作区持久化、LR 导出不变。已完成 v1.5.6 发布构建与 EXE 自检。

## 依赖和设计依据

按用户要求，将 UI UX Pro Max 安装到个人 Codex skills/ui-ux-pro-max；该技能及其搜索脚本不随产品打包。运行设计系统搜索后剔除宣传网站模式，采用专业工具对应的 Minimalism & Swiss Style 建议：功能优先、对齐网格、单一强调色、统一层级。

项目虚拟环境安装 ttkbootstrap 2.2.3，pyproject.toml 固定版本。继续使用 Tkinter/ttk，不启用 enable_global_api，不替换控件构造函数。自定义 photo-cull-light 主题作用于同一 Tk 解释器；页面布局按任务分别调整。主题只初始化一次，并在根窗口销毁时释放 Style/Fonts，避免关闭子窗口破坏父窗口。

## 样式规范

颜色和字体集中在 ui_style.py。Microsoft YaHei UI：正文 10pt、辅助 9pt、快捷键 8pt、标题 11pt 粗体。背景 #F4F6F8，正文 #303640，辅助 #626B77，边框 #CFD7E1，蓝色强调 #466B97，选中 #E5EFFB，照片区域 #303030。

主页外边距 24/16px，表单标签与输入对齐；六流程按钮同排同权。停止/继续等辅助操作降低视觉权重，清空工作区使用危险色。API 保存、候选采用使用实心主按钮。帮助与 LR 插件相邻，保留 Alt+1～4、F1。API 窗口减少留白，切换预设或标签时不重设窗口位置。

## 验证

实际 Python/Tk 桌面窗口截图在 build/visual-a，不是 HTML。测试使用临时配置与生成的示意图，不调用 API、不读写用户工作区。

覆盖主页 960x640、API 925x575、候选 1100x650，以及大字体 1400x780；检查长路径/文件名、空候选、缺图、长错误提示及按钮边界。Windows 实际缩放 125%；另用 Tk scaling 模拟 100/150/200%，没有验证真实多显示器 DPI 切换。

相关样式、API 配置、快捷入口、窗口、处理控制与候选回归测试通过。测试进程重复创建 Tk 根时出现环境 Tcl 初始化失败，受影响用例在独立进程重跑通过；没有修改业务代码绕过该问题。pip check 与 git diff --check 通过。


## A 方案第二轮

顶部白底紧凑工具栏，移除常驻快捷键小字，悬停显示 Alt+1～4/F1，原键盘绑定保留。主页/API/更新/LR 对应入口显示浅蓝选中态；子任务不错误高亮其他入口。帮助与其他入口统一尺寸、位置、字体。

六类页面共用字体、按钮、表格选中颜色；人脸预览使用深灰背景和浅色提示文字。组编辑保留虚拟化画布，改变绘制配色和字体，不改变加载/分组。AI 提交按钮改为一行，精选再选放在偏好末行，减少大字体下批次列表被挤压。照片示意图仅用于布局验收。

本轮相关测试：顶部和主题 3 项、组编辑与裁切 12 项、AI 选片 25 项通过。实际桌面截图涵盖新增三页、网页选片、结果标签页；100/125/200% 字体测试不等同真实 Windows 多屏 DPI 测试。源码已调整，v1.5.6 发布 EXE 自检通过。
