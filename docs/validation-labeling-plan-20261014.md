# 风景弃置与相似分组标注验证方案

日期：2026-10-14。状态：待确认、待执行。本文件只定义标注和验收方法，没有新增数据、运行模型、修改代码或阈值，不包含新的准确率结论。

## 当前边界

- 风景可靠自动弃置仍未完成。`analysis_modes.landscape_evidence()` 只输出 `keep/review`，`assess_asset_mode()` 的风景分支返回 `rejected=False`。现有合成与流程测试不能证明真实照片弃置准确率；零弃置不能被包装成“可靠弃置”。
- 分组采用工作区内 dHash、灰度块结构、宽高比和固定代表检查，没有时间或目录邻近门槛；三个预设是未校准的工程默认值。
- 本方案补充 [需求验收矩阵](requirements-acceptance-20261013.md) 的风景校准和真实分组精度缺口，不关闭 Windows、Lightroom、全机型解码或发布许可门槛。

## 一 样本和最小记录

只使用经允许的本地素材或另行批准的公开素材；本次不下载、上传或调用付费服务。真实照片、路径映射和逐图标注留在约定的私有验证位置，不入 Git。新增素材来源、数量及授权待确认。

必须区分四层身份：

| 标识 | 定义 |
| --- | --- |
| `asset_id` | 一次曝光的逻辑照片；同曝光 RAW/JPG 不重复计数 |
| `variant_family_id` | 原图及复制、裁切、缩放、编辑、合成模糊等衍生版 |
| `comparison_group_id` | 人工认定应放在一起比较取舍的相似组，单张也有独立组 |
| `scene_family_id` | 防泄漏划分单位；同一场景或高度相关拍摄序列，可包含多个应分开的比较组 |

准备四份私有清单，格式可选 JSONL 或 CSV：

1. 素材：上述 ID、原始哈希、来源授权、设备格式与尺寸、RAW/JPG 配对、可读取状态、历史接触记录、集合及排除原因。
2. 风景标签：下节标签、证据来源、标注者原始意见、理由与裁决。
3. 分组标签：人工成员、边界 pair、歧义原因、预定工作区与增量导入序列。
4. 预测：稳定 ID、本地建议、自动组成员与固定代表、解码来源、代码/依赖/配置版本、运行状态和对应真值版本。

保留完整序列和工作区候选集合，不只挑明显模糊或历史失败图。代表性抽样用于估计日常风险；故意挑选的困难压力集单独报告，不能把其类别比例推广到日常使用。至少核对以下覆盖，缺项注明“未覆盖”：

- 风景：清晰、严重意外模糊、轻微软化、低纹理、浅景深、刻意虚化、长曝光、雾气、低照度/噪声、不同主要景物和构图。
- 分组：非相邻、跨目录/日期、近似色调但不同场景、重复纹理、颜色差别、裁切/旋转/宽高比变化，以及 A 近似 B、B 近似 C、A 与 C 应分开的链式边界。
- 来源：JPG 优先、仅 RAW、坏 JPG 回退、预览不足、读取失败及真实可用格式。合成图不替代真实摄影或格式验收。

## 二 风景标签与例外

先看统一条件下的适屏全图，再看原生 100% 主要景物细节，记录来源、方向和尺寸。不得用模型建议或锐度值反推真值。人工可私下记录关注区域，不要求产品新增风景框选。

| 标签 | 判定条件 |
| --- | --- |
| `K` 技术上不应弃置 | 主要景物满足约定用途，或已确认合理刻意效果；不要求全图清晰，不代表审美佳作 |
| `D` 明确可技术弃置 | 主要景物严重意外失焦/拖影，有有效细节证据，已排除低纹理、正常景深与刻意效果，按约定用途不可用 |
| `U` 必须复核 | 边界软化、主体/意图不明、证据不足或标注分歧未解决 |
| `X` 不适用或无参考 | 超出预先约定范围，或无法取得有效参考；必须记录原因，不能事后借此删除失败例 |

同时记录技术状态（清晰/严重意外模糊/边界/不可判断）、证据充分性、意图（普通/刻意/未知）及例外标签。审美偏好、重复照片和“同组另一张更好”另记，不能成为技术 `D`。

- 天空、水面、雪地、白墙等低纹理不能因锐度低标为 `D`；正常表现可为 `K`，无法判断则为 `U`。
- 正常景深、长曝光水流、跟拍拖影、抽象或刻意全图虚化，经确认符合意图为 `K`，意图未知为 `U`。
- 一处清晰不保证关键主体清晰，一处模糊也不证明整图失败。雾、热扰动、噪声、降噪、压缩和曝光问题分别记录；是否扩展弃置原因需用户确定。
- 只有低质预览或读不出文件时为 `U/X`，不能把读取失败当作照片模糊。产品面对这些输入仍应不弃置。

建议安全关键标签独立双标，先不展示算法输出；分歧由第三人或用户裁决，仍无可靠结论则保留 `U`。记录原始一致率、分歧和裁决数，不只展示裁决后的结果。

## 三 分组真值

建议“同组”定义为：同一主体或景物、足够接近的构图与拍摄意图，适合放入同组选片比较。地点/日期/色调相同不够，目录不同或时间间隔长也不应自动拆组。质量差异本身不拆组。曝光包围、焦点堆栈、全景分片、不同姿态和构图如何处理，先由用户确定并冻结指南。

在完整工作区建立人工分区，给组写明共同依据与边界；单张明确标出。对困难边界另记 `same/different/ambiguous` pair，不把歧义默认当不同组。若 A-B、B-C 为同组而 A-C 为不同组，必须裁决整个边界，不用传递闭包强行合并。无法形成一致分区的边界放入歧义压力集，报告排除范围及产品输出，不进入明确真值的主指标。

- 误合并：人工不同组，自动同组。
- 误拆分：人工同组，自动不同组。
- 污染组：一个自动组混入至少两个明确人工组。
- 碎裂组：一个人工组被拆成多个自动组。

主精度测试从无人工覆盖的干净副本开始。已有手工组不是自动算法的准确率成果，也不能未经盲复核直接作为真值。增量导入、代表缺失、稳定 ID、人工组保护、输入顺序和预览缺失另外做流程验收；重分组不得改变人工/AI 决定或原片。

## 四 开发与独立留出

1. 先登记历史接触。旧 PIQ/CERTH 评估图及相关衍生图只能作历史诊断/开发资料，不能重新随机划分后称独立留出。[历史清晰度验证](clarity-v2-validation.md) 中参与过诊断的保留连拍组也不是独立盲测；历史不明的先隔离。
2. 用哈希、近似图核对和人工场景判断整理变体族、场景族。原图与所有衍生版、同连拍、同场景的不同构图、相关跨日期重拍不得跨开发/留出。划分单位必须大于或等于人工比较组；只按照片、文件夹或日期随机划分不合格。
3. 在场景族层面分层划分，记录规则、随机种子、比例、独立场景族数和照片数。开发内部调参或交叉验证也按场景族隔离。比例与数量由所需风险精度和真实可用场景数决定，暂不虚设数字。
4. 独立保管者封存留出图像、标签和逐例结果，开发者冻结前不得查看。若没有独立保管或未见条件，就称锁定回归集/开发验证集，不声称盲测。
5. 先冻结代码、依赖、解码设置、主预设、标注指南、数据清单哈希、排除规则、主指标和通过门槛，再正式评估留出。不能看完留出再在三个预设中挑最好者当无偏结果。
6. 查看留出失败后改过规则/阈值，该集转为历史回归；下一轮独立验收要用新的未见场景族。重命名、重抽样或隐藏标签不能恢复独立性。

合成图继承原图划分，增加变体不增加独立场景数。每个评估工作区只含同一集合的场景族，但需包含足够多不同场景来测跨场景误合并；不能在开发阶段先对混合开发/留出工作区运行分组。

## 五 指标和验收解释

### 风景

只评本地建议及对应证据，人工和 AI 结果另报。先给出 `K/D/U/X` 对 `keep/reject/review/读取或运行失败` 的完整计数。令 `N=K+D+U`，`R` 为其中建议弃置数，`rK/rD/rU` 为各类被弃置数：

| 指标 | 定义 |
| --- | --- |
| 明确可保留照片误弃率 | `rK/K` |
| 非安全弃置率 | `(rK+rU)/R`，证据不足 U 不算安全弃置 |
| 安全弃置精确率 | `rD/R` |
| 弃置覆盖率 | `R/N` |
| 明确坏片检出率 | `rD/D` |
| 待复核率与运行失败率 | 各自数量 `/N`，并报合计人工处理负担 |
| 明确坏片放行率 | `D 中输出 keep 的数量/D` |

分子分母与比例同报，零分母记 `N/A`。`X` 数量和原因另报；产品对 X 的弃置仍作为输入安全问题审查。报告总体、场景族宏平均和关键例外/解码分层，样本不足记“证据不足”。

若 `R=0`，覆盖率为零，弃置精确率/非安全弃置率无定义；存在 D 时检出率为零。当前结构性保守基线不能通过可靠自动弃置验收，真实运行计数仍需实际测量。

区间以场景族为相关单位计算，不把连拍当独立试验。少量场景或零错误时，不用零宽 bootstrap 区间声称风险为零；可另报场景族“是否发生任一误弃”的事件区间，但不能冒充照片误弃率区间。区间方法、置信水平与所需场景数在看留出前确定。

### 分组

在预定义工作区的全部可判定无序照片对上计算，不只统计算法检索出的候选对。若只能抽样，事先登记抽样概率、加权方法和区间；便利抽样不能称全量。歧义边界另报数量与自动同组率。

- `TP` 人工同组且自动同组；`FP` 人工不同组但自动同组；`FN` 人工同组但自动不同组。
- pair 精确率 `TP/(TP+FP)`，召回率 `TP/(TP+FN)`，F1 `2TP/(2TP+FP+FN)`。
- pair 误合并比例 `FP/(TP+FP)`，误拆分比例 `FN/(TP+FN)`；零分母为 `N/A`。
- 另报污染组与碎裂组数量/比例、被影响照片数、完整恢复人工组比例（单张/多张分开）、碎片数和最大错误合并规模。
- 同时报工作区/场景族宏平均和分层结果，避免大连拍支配微平均；跨场景误合并必须单列，不能在逐场景统计时遗漏。不要用大量容易负对占主导的全 pair 准确率作主指标。

## 六 待用户决定与执行顺序

以下均待确认，本文不设置程序阈值或承诺达标：

| 决策 | 需要确定 |
| --- | --- |
| 用途与标签 | 摄影范围、输出用途、弃置原因；包围/堆栈/全景/姿态的同组含义 |
| 安全上限 | 可保留照片误弃率、非安全弃置率的上限及置信水平；关键例外是否一次误弃即失败 |
| 实用下限 | 最低弃置覆盖率、坏片检出率、可接受复核/失败负担 |
| 分组门槛 | pair 误合并/误拆分上限、污染/碎裂组容忍度、最大错误合并规模 |
| 数据要求 | 新素材授权与来源、最少独立场景族、关键分层覆盖、开发/留出比例及保管者 |
| 通过与权限 | 主预设、哪些指标必须同时通过；后续评估脚本、素材收集和代码修改的授权范围 |

最小执行顺序：确认上述决策 → 清点素材与历史接触 → 开发集双人试标并冻结指南 → 场景族划分与留出封存 → 经授权测量保守基线、在开发集研究候选 → 冻结候选与指标 → 留出正式验收。

交付物为数据清单摘要、标注分歧/排除说明、带分子分母及区间的分层报告、脱敏失败例和逐项“通过/失败/证据不足”。安全上限与有效覆盖下限必须同时满足才称风景弃置达到约定门槛。有限样本零误弃不证明真实风险为零；不达标则保持待复核。新一轮改动需新的未见验收材料。方案或验收通过均不自动授权推送、发布或替换用户程序。
