# 扫描性能改进（v1.2.3 后续源码）

本轮实现阶段耗时统计、逐张增量保存，以及自动受控并行。人脸检测阈值、原尺寸清晰度分析和弃置规则保持原逻辑。

## 自动选择并行数量

扫描图片和重新扫描修改照片时，先串行处理前两张，期间每 50ms 采样进程内存。之后每批根据 CPU 逻辑核心数、当前可用内存和观测到的单张内存增量，在 1、2、4 张中选择：

- 少于 4 个逻辑核心最多 1 张；4～7 个最多 2 张；8 个及以上最多 4 张。
- 内存预留取 2 GiB 和总物理内存 25% 中的较大值。
- 单张预算至少 512 MiB，观测峰值增量另加 25% 余量；内存读数缺失时使用单张。
- 每批重新检查可用内存，不一次性把整批照片放入工作队列。低内存只减少后续派发，不强行中断解码。

内存估计不是精确上限，特别大的 RAW、其他软件突然占用内存仍会影响速度。多人脸和身体实验检查也可能增加工作量。API 清晰度复核保持原来的串行请求方式。

点击停止后，不再派发新的批次；当前已启动的少量照片完成并保存后停止。继续时重新评估资源，未完成照片使用继续时的设置，已完成结果保留原设置。

## 逐张保存与恢复

每张完成时仅写该照片的结果、设置和进度增量，不再反复序列化全部照片。阶段切换、正常停止等边界写完整汇总。增量使用原子替换，重启按序号恢复；不完整临时文件不参与恢复，缺号和损坏不会被默默跳过。

任务记录使用版本 2，新代码可以读取旧版本 1 的中断任务；旧 EXE 不能继续新版产生的未完成任务，请用新版继续。任务完成后的工作区格式仍兼容。

## 日志中的耗时

结束或停止时记录本次实际耗时，以及累计的预览生成、人物检测、RAW/原图解码、清晰度分析、结果保存、分组耗时。嵌套计时去除重复统计；不同工作线程的耗时相加，因此累计工作时间可能大于实际等待时间。未列出的任务准备和最终发布等时间仍包含在实际耗时中。

这些数据用来定位耗时环节，不上传照片或配置。首次扫描与缓存命中的耗时不能直接比较。分组特征复用、合并人脸与身体的 RAW 解码不属于本轮改动。

## 验证

测试覆盖资源降档、4 张真正同时运行、停止后保存已启动批次、增量独立恢复、继续使用新设置、旧中断任务迁移，以及 1000 张清单中单张保存只序列化一个资产。真实 RAW 小样本用于核对自动并行和串行判断一致性，不作为大规模固定加速倍数承诺。
# 共享解码与自适应并行（v1.3.1 后续源码）

开启身体检查时，人脸和身体检查在单张照片范围内共用一次延迟加载的原尺寸图像；缓存命中且无需原图时不解码。线程之间不共享照片，处理完成和异常退出都会释放图像。关闭身体检查沿用原有释放时机。原尺寸、白平衡、清晰度指标、阈值均保持不变。

并行档位扩展为 1/2/4/6/8。CPU 和可用内存只决定上限（少于 4 个逻辑线程上限 1，4–7 上限 2，8–11 上限 4，12–15 上限 6，16 及以上上限 8）；仍预留至少 2 GiB 或总内存 25%，参考前两张单张处理时的峰值增长，加 25% 余量，单张预算最低 512 MiB。

首次从 2 张开始，每档至少观察 3 个完整批次、12 张照片，以实际每秒处理照片数比较。升档提升不足 8% 就回退，并停止本轮继续升档。末尾不足一批及受到资源限制的批次不参与比较；内存不足时下一批立即降低并行数。停止仍等待当前已派发批次完成并保存，最多 8 张。

已测得的档位保存在运行数据目录 settings/scan-performance.json，按 CPU 标识、逻辑线程数、总内存和身体检查开关区分。下次先参考缓存，但会重新测量并向下一档复核，再决定是否向上探索；缓存不是固定强制并行数。照片内容和后台负载会影响测速，8% 为保守实用阈值，不保证全局最优。OpenMP 默认解码线程保持不变。

验证：63 项相关自动测试通过；8 张真实 RAW 开启身体检测，完整解码由 16 次变为 8 次，清晰度证据、分数和判定完全一致。该小批次本次用时 21.8 秒→14.3 秒，不作为所有照片的固定提速承诺。尚未打包 EXE，未接入 GPU。

# 完整日志与扫描诊断

后续源码将逐张诊断和原有日志统一写入工作区 `logs/session.log`（旧布局沿用根目录 `session.log`）。以 `[扫描诊断]` 开头的 JSON 行只保存到文件，主页面运行时和重启恢复时均不显示。原有进度、错误、结果及阶段耗时摘要保持显示。

每次扫描/继续/重新扫描有独立 run_id，记录本次完成照片的文件名、处理耗时、阶段耗时、预览来源以及解码/检测调用次数和耗时；停止时也写入本次已完成照片汇总。汇总包含最慢 10 张。记录不包含照片像素、提示词或 API Key，不触发额外模型推理或 API 请求。

`raw_full_decode` 为清晰度分析使用的原尺寸 RAW 解码，`raw_preview_half_decode` 为预览提取失败后的半尺寸解码，二者分别统计。预览来源还区分已缓存、配对 JPEG、内嵌 JPEG/位图和普通图片。`yunet_normal`、`yunet_rotation` 统计模型调用，`head_detection` 和 `head_face_retry` 记录头部定位及局部补救；后者可能包含 YuNet 调用，诊断操作耗时存在嵌套，不应直接相加作为总时间。

诊断写入失败不阻断扫描。完成照片实时追加；突然退出时可能没有汇总或最后一条记录，不将诊断当作任务恢复依据。工作区归档会一起保存完整日志。此次仅更新源码，使用前需重新打包 EXE。
