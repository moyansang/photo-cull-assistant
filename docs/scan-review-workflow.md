# 扫描结果与依据：本地纠错、选片与交接

本轮从 `d0bbd2276de5e3fba9b779cefddd646f884edcf1` 接续。它是源码功能，不是已安装 EXE；现用 build17 与独立 build18 均未替换。评分器、阈值、主体自动选择规则、分组算法、模型和依赖声明未改。

## 日常入口

1. 在主页选择照片／既有工作区，使用原有“扫描图片”；点击新增 **扫描结果与依据**。
2. 默认优先看弃置、待确认和失败；“全部结果”保留所有已扫描输入。来源缺失／变化时仍可查看历史，明确过期，不把失败当弃置。照片目录整体离线时，明确选择已有工作区后可只读打开历史；不激活重算、改组或 LR 导出。
3. 整体／原生 100% 支持平移、缩放，显示来源成员、像素和倍率。图层分别标记实际已记录的检测候选、选用、人工确认。来源或坐标不匹配不叠加；历史眼带／脸核心缺逆变换只显示原证据和缺项，绝不用当前参数补画。眼带不是逐眼评分，AF 不是合焦证明，手部未支持。
4. 可写一句疑问，或在图上框关注区域保存草稿；普通照片无需填写。反馈编辑／撤回留历史，不改变技术建议、人工决定或分组，不调用 AI。
5. **应用范围并重新检查** 必须另行确认。当前可靠粒度为一张照片整张重测；只支持 face（脸）范围的应用，body/hand/other 只存待支持草稿。此框替换该照片已选人脸，既有身体选择保留，确认前须检查其仍属于本次主要人物。多人复杂修改仍用原人物编辑页（旧页保存的自动重分组语义不因本轮改变）。新纠错入口不重新分组。
6. 重查先保存原建议／原因／来源／范围快照，新结果与新范围及前后记录一起事务发布。主页“停止处理”后可“继续处理”；若修改了草稿或来源、旧任务不能发布，可在结果页 **取消未发布的重查**，保留原结果和反馈，再重新操作。运行中先停止并等待。发布或保存失败不显示成功；取消前的确认框可直接取消。
7. 选同组两张照片并排比较；各图独立定位／100% 查看，不假定跨照片主体已匹配，不生成新的相对技术结论。组选片入口复用原拆分／合并；AI 摄影选片只导航，须在原页面明确启动服务。
8. 人工留弃、星级与疑问分开。默认“沿用建议”不隐式保留；只设星级不替用户批准留弃。清星级为显式 `0`；“不设置”不覆盖 LR 已有星。撤回人工决定回到当前有效建议，旧技术问题和过期 AI 证据不复活。
9. **Lightroom 导出** 复用原项目和插件 JSON。生成文件不等于 Lightroom 已应用。人工保留也保留技术待确认字段；0 清星需使用本提交对应插件，旧插件不能接受 0。原照片与 sidecar 均不写。

## 存储与兼容

- `scan-review.json` 是附加格式 version 1，记录问题／关注范围、反馈时身份观测与原证据快照、修改历史、重查前后、失败／中断。稳定键兼容既有 photo_id，附大小写敏感原路径身份区分，不按 stem 重连照片。关联只沿用扫描资产已有 RAW/JPEG 成员；本轮没有新配对算法。
- 缺失历史运行 ID、范围版本、实际测量区域明确列为缺项。反馈时观测不是事后补签测量收据。
- `scan-session.json` version 1、`ai_project.json` version 1 与既有工作区仍可读。人工最终值仍以 `ReviewProject` 为权威，不另造决定数据库；新增字段级确认标志、撤回历史是附加字段。
- 新结果页只读读取旧会话；来源不可用保留旧列表与证据，仅在内存标记过期。旧 API 默认恢复方式不变，明确扫描／迁移仍走既有流程。对有旧归档或损坏子记录的情况，不静默当空数据覆盖。
- 反馈 CAS＋跨进程锁拒绝旧版本保存；AI 项目增加文件版本检查防旧页面覆盖人工决定。新重查沿既有发布日志、回滚及恢复机制，新增范围／对照与 session 同步提交。中断 checkpoint 不代表新结果已发布。
- 私有诊断含路径、原文、证据，仅明确导出到工作区外 JSON；脱敏导出按允许字段集合去掉路径、自由文本与原始证据。没有自动上传。

## 成本与边界

查看／筛选／反馈不增加评分或 API；原生查看会本地解码当前来源（可能有内存和读取等待），不下载模型。显式应用才有一张整图的原生产测量成本。保存附加历史增加本地 JSON 体积，目前不做历史压缩或全面迁移。来源快速签名不是内容哈希；无法识别所有 stat 完全保持的原地替换。

本轮未实现逐眼／手部评分、全面区域持久 ID 迁移、区域增量测量、新本地摄影评分器、算法实验、学习／训练、自动重分组、新 LR 回执协议。未改变艺术性模糊／噪声／表情等自由文字的原意。
