# 清晰度改进与实验开关（源码版）

本轮只更新源码，不更改已发布的 v1.2.1 EXE。旧工作区保持既有结果，只有明确扫描或重新扫描照片才启用新版本地证据。

## 当前流程

1. 扫描图片：用真实人脸关键点检查原尺寸眼部与脸部细节，再进行分组及可比较连拍的相对检查。明确模糊弃置，证据不足待确认。
2. 调整人脸后，仅重新扫描修改过的照片。切换实验开关不会重算已完成结果；继续任务时只有未完成照片使用当前设置。
3. AI 复核：提交总览、原尺寸眼部和脸部局部，校验结构化失焦／拖影观察与结论。明确模糊直接弃置，冲突和失败跳过保持待确认。
4. API 与网页选片均只接受明确清晰的照片。待确认照片可直接导出到 Lightroom 的“清晰度待确认”智能收藏夹，不写 AI 星级或留用／弃置标记；模糊弃置结果一起导出。

## 身体清晰度检查（实验）

主页面勾选开关，默认关闭，按工作区记忆；需同时开启本地技术检查。它检查所选主体的躯干和主要肢体区域，不以路人、指尖或衣摆的轻微运动直接弃置。

疑似身体拖影会转待确认；执行 AI 复核时附带最多三个原尺寸身体局部。模型必须同时提供身体清晰的证据才允许通过。人物关联、姿态或纹理不可靠时保持待确认；如果脸已经清楚，不为无法定位的身体单独发 API 请求。没有 API 也可以把待确认结果导入 Lightroom 检查。

模型来自固定版本 OpenCV Zoo，见 [模型来源与许可证](../body_models/README.md)。源码运行前执行 `python body_models/download.py`，只在准备环境／构建时下载，处理照片时不联网下载模型。缺少模型时开启实验检查会保持待确认，不会假装身体检查通过。

## 标注样本验证

以下是用户主动挑选的问题样本，不是随机抽样，不能视作整体准确率。

| 生产本地流程 | 判清晰 | 待确认 | 弃置 |
|---|---:|---:|---:|
| 已知模糊 34 张 | 3 | 28 | 3 |
| 已知清晰 14 张 | 13 | 1 | 0 |

旧版本地直接放行了上述模糊样本中的 28 张，新版为 3 张。仍有漏检；不能保证所有本地通过照片都清晰。按完整连拍组划分的保留部分为 11 张模糊（10 待确认、1 弃置）和 4 张清晰（均通过），这些照片曾参与诊断，因此不是独立盲测。

人脸 API 实测严格限定为十张、每张一次、不重试：6 张历史漏检均返回模糊，1 张历史误弃置及 3 张清晰对照均返回清晰，总计 15,532 tokens。只验证该批人脸输入和提示词；没有用付费 API 实测身体提示词。

身体实验的 4 张已知身体模糊均转为待确认；14 张清晰对照中，1 张缺少已选人脸，其余 13 张为 2 清晰、11 待确认，没有直接误弃置。待确认过多，因此默认关闭。身体分析实测约 0.28–1.10 秒／张，额外 RAW 解码约 1.25–1.81 秒／张；速度随硬件和图像变化。

## 实际提交证据

工作区 `focus-evidence` 保存 API 实际发送的 PNG、提示词和原始回答。图片按内容去重、ZIP 压缩，普通配置仅记录模型和地址，不记录 API Key。该目录独立于可删除的分析缓存，工作区整理后仍保留，LR 导出仍在工作区外露保存、不压缩。清空工作区会一起清除这些证据。

用户照片、逐张诊断及凭据不进入 Git。源码测试覆盖准入／LR 导出、原尺寸裁切、结构化回复冲突、证据保存、实验关闭、身体待确认、设置记忆及停止续跑。
