# Windows Tk 测试捕获隔离

本地 CPython 3.12.13（uv 已安装运行时）/Tcl 8.6.12 在 pytest 默认 `fd` 输出捕获下，重复创建 Tk 时出现间歇初始化错误：`tcl_findLibrary` 不存在，或 `init.tcl`、`tk.tcl`、`listbox.tcl`、`scale.tcl` 读取失败。这些库文件实际存在；错误发生于 `App.__init__` 的 `super().__init__()`，在设置读取、工作区恢复和证据功能执行前。

诊断复现保留了全部断言：

- 默认捕获运行工作区模块：9 通过、2 初始化失败；去掉现有垃圾回收 fixtures 后仍有 1 失败。
- 显式设置已有 Tcl/Tk 库路径仍有 2 失败；保留一个 Tcl 解释器的临时试验仍有 1 失败。因此没有采纳这些修改，也没有改全局 Python 环境。
- 原失败测试单独通过。独立单线程纯 Tk 初始化在两套已安装 Python 中各 100 次通过；不通过 pytest、连续创建关闭临时设置应用 30 次通过。
- 只改 `--capture=sys` 后，原工作区模块三个独立进程连续各 11 项通过（33/33）。未跳过、标记 xfail 或重试失败测试；没有安装新工具。

因此将项目默认 pytest 捕获设为 `sys`，避免每个用例替换操作系统文件描述符。Python 输出仍被捕获；原生库输出可能直接出现在终端，可通过进程级日志重定向记录。现有主线程垃圾回收隔离保持不变。证据支持故障与本运行时的 fd 捕获交互相关，不把尚未追踪到的 Tcl 内部机制或并发原因当作已证实事实。

普通验证命令仍为 `python -m pytest -q`，自动使用该配置。不要为“通过”覆盖捕获配置、静默重试或跳过失败。应用及打包 EXE 不读取 pytest 配置，运行行为未因此更改。
