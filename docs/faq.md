# 常见问题

[返回首页](../README.md)

## 删了一些照片，为什么以前打不开工作区？

旧版将任何缺图视为整份扫描失效。v1.5 会移除缺图记录并保留其余分析；照片列表改变后重新生成联系表即可。已有导出文件不会被自动改写，要重新导出再导入 Lightroom。

## 新照片需要把所有 RAW 再扫一次吗？

v1.5 会在日志提示新增文件数，点击扫描图片走增量流程；保留旧照片分析与分组，新增照片另行分组。RAW/JPG 配对变化也属于需要处理的输入。无新增时点击扫描仍可执行全量重扫。

## 为什么新增数量和扫描张数不同？

提示按文件计数；同名 RAW+JPG 可能合为一张逻辑照片。不同子目录同名文件仍可能冲突，建议分批处理。

## 没有 API Key 能用吗？

可以。本地扫描、修正、分组与联系表不需要 API；网页页可合并批次，手动上传材料并导入回答。待确认的清晰度问题可在 Lightroom 的智能收藏夹检查。

## 清晰度检查仍漏掉模糊照片怎么办？

先核对人脸框是否真的在主体脸上，以及脸部像素是否足够。可以调整后只重扫改动图片，再进行 API 复核。提高或降低人脸检测置信度不等于调整清晰度阈值。最后在 LR 原图复核；模型不能保证无漏检。

## 分组灵敏度会改变人脸检测吗？

不会。严格/标准/宽松控制分组，人脸检测置信度在独立的人脸设置中。重扫和人工调整请按当前页面说明操作。

## 1000 张 RAW 很慢，GPU 有用吗？

正式版没有 GPU 后端。当前通过共享解码、自适应 CPU 并行、分析缓存和增量保存减少重复工作；速度取决于 RAW 大小、CPU、内存和磁盘。日志中的累计阶段耗时不是实际总时间，见[性能说明](scan-performance.md)。

## 关闭后为什么还占空间？

照片预览可重建；联系表、AI 提交图片和 LR 导出有意保留。活动处理任务、原片/记录不可验证或目录与原片重叠会阻止整理。查看日志中的整理结果，不要直接删除任务恢复文件。

## LR 显示 RAW 匹配、JPG 未匹配是什么？

插件分别按完整路径查找 Catalog 中的 RAW 和 JPG。若只导入 RAW，JPG 未匹配是正常的；已匹配 RAW 仍可应用结果。插件不负责把照片导入 Catalog。

## 在 LR 哪里看 AI 回复？

选中照片，图库右侧元数据面板的下拉菜单选“AI选片助手”。先更新插件并导入新版结果，才会显示评分理由、清晰度理由及待确认事项。插件字段不覆盖原照片标题和说明。

## 弃置会删除照片或生成 XMP 吗？

不会删除。插件应用 Catalog 的旗标/星级/专用元数据；它自身不写 XMP。Lightroom 若开启自动写 XMP，仍可能自行写入。

## 如何报告问题？

附版本、Windows/CPU/内存、相机与照片格式、操作步骤及相关日志片段。不要提交 API Key；涉及真实图片时可先给不含敏感内容的截图或最小复现样本。[提交问题](https://github.com/moyansang/photo-cull-assistant/issues/new/choose)
