## 有界真实 RAW 内存验证

使用此前已核验来源和 SHA256 的五份 CR3/ARW/RAF/DNG/ORF，复制到独立目录，全部调用生产 `load_display_image(full_raw=True)`，约 20–30MP，无合成伪 RAW。

- 顺序解码五图两轮，共 10 次：通过；内核最大 RSS 558.51 MiB，10ms 采样峰值 558.70 MiB。两轮清空缓存后 RSS 28.96/28.96 MiB。
- 两个调用线程请求 CR3/ARW，重复两轮，共 4 次：通过；内核最大 RSS 664.27 MiB，采样峰值 664.61 MiB。清缓存后 RSS 85.88/78.31 MiB。调用端可并发，生产信号量仍只允许一个原生解码器进入，不是两个原生解码器并行。
- 每次观察的缓存不超过 128 MiB；每轮清空后 entries=0、bytes=0。全部原始照片和隔离副本前后 SHA256 不变。
- 每个子进程设置 3 GiB 地址空间上限、1.25 GiB RSS 停止线、120 秒超时；主机可用内存低于 2 GiB 则停止。原生数值线程限制为 1。没有触发停止线，没有耗尽共享机内存。

这是限定输入、两轮、单一 Linux 环境的实测，不是长期泄漏证明、极低内存故障测试、通用内存上限或 Windows 性能保证。RSS 包含原生库和调用者图片，128 MiB 只是缓存上限。未清系统文件缓存，耗时不是性能基准。

证据：`native_memory_probe.py`、`memory-summary.json`、`memory-serial.json`、`memory-two_threads.json`及对应原始日志。

## 发布中断的实际缺陷

使用独立进程、生成 PNG 和临时混合工作区，在真实 `ProcessingJob._publish()` 的路径移动/JSON 写入后调用 `os._exit(86)`。不运行退出清理或 Python 异常回滚。三个流程共 10 个断点：增量扫描 3、全量扫描 4、联系表 3。

旧实现结果：

- 全量扫描的预览已移入正式目录、或 settings 已写之后退出：重载仍检查旧暂存预览，报“已完成的预览文件丢失”，随后删除 job root 及 backup。
- 联系表已移入正式目录、或 settings 已写之后退出：同样因旧暂存联系表缺失误清理。部分断点尚未写新 session/source marker，正式工作区因此不完整。
- 增量扫描最后写 settings 后退出：续跑函数返回成功，但再次打开 session 后，新图 B 的 preview_path 指向已清掉的 staging。不能只用“无异常”作为恢复成功。
- 10 点中 4 点明确恢复报错、1 点潜在预览失效，5 点重开后可用。旧联系表在成功新扫描后失效是预期行为，不能把这一变化本身算作缺陷。
- 所有原片不变；原人工/AI/导出/证据样本字节保留。崩溃工作区在尝试恢复前另存了一份完整副本，失败的自动清理没有消灭本次复现证据。

这是进程终止实验，不是断电/磁盘缓存丢失实验，没有 fsync 持久性保证。初版探针误把增量预览目标设为全量目录，一次注入未命中并明确报错；保留日志，未计入最终 10 点结果。

## 候选修复与验收

生产改动限于发布/恢复，不改 UI、照片判定、分组阈值或原片：

1. `publication_transaction.py` 在移动之前记录合法目标、旧快照、暂存快照及 SHA256；被动 JSON 预记将写入的精确字节 SHA256。
2. 未提交事务先把已移出的新文件归还 staging，再恢复旧快照。旧备份作为不可消耗副本，恢复时复制并原子替换；原路径已经正确则不重复删除。需移除的公开目标先原子移入事务内部，再清私有副本。
3. 回滚自身可以再次被终止。只有旧快照与 staging 全部核验后才进入 rolled_back 并清备份；此阶段允许继续清理上次中断留下的部分备份。
4. 已提交事务核对新文件与预期 staging/JSON 内容，然后写 committed。重启验证已提交快照，正确收尾，不重跑旧 staging 任务。
5. 外来修改、损坏或无日志旧备份保留报错；不通过关闭缺失校验或删除 backup 达成“通过”。任务创建、加载、运行及focus重试/跳过使用同一线程/进程锁；操作前持锁刷新checkpoint，完成后的旧对象不能重新制造任务。未解决事务不写回旧 job.json、不被普通失效清理删除。

新增 `tests/test_publication_crash_recovery.py` 使用真实子进程退出，覆盖完整/增量/联系表的备份后、移动后、settings 后、commit 后；恢复再次退出；私有 backup 清理中途退出；外来修改；损坏/无日志/非法快照保全；跨进程锁；回滚失败后重试和旧对象拒绝重跑。验收包含旧发布快照逐字节恢复、再次运行、重新打开 session、所有预览与联系表可读、人工/AI/导出/证据与原图保持。
