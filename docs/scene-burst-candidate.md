# Scene/burst/cohort portrait grouping and presets

Build 16 derives from the frozen v9 candidate (`507da7dd07036eb6633d0cb896e4d407bf0d3173`) and build-15 history. Local adoption requires new-source regression and actual packaged-EXE acceptance. No remote publication, API request or model training is included. Historical v9 evidence remains frozen separately.

Portrait grouping reads prepared image pixels, capture times and geometric face/body regions. Quality/rejection recommendations, sharpness scores, AI verdicts, stale/dirty flags, person-review state, decisions and ratings do not determine membership. A `decode_error:` note is an input-validity failure, distinct from blur. Reserved unreadable placeholders and corrupt prepared images are not photo evidence.

The burst policy uses a 12-second maximum gap and 90-second span, fixed group camera references and a bounded, first-corroborated multi-person reference. It prefers supported camera correspondence to an unknown camera result. An unknown affine model's inlier ratio cannot rank groups. Group IDs are deterministic for the same inputs; incremental imports preserve prior memberships and saved anchor identity. Missing/conflicting saved anchors do not silently move to another member. Protected manual groups cannot serve as bridges, including absent reserved IDs.

Background ORB correspondence is mutual, geometric and spatially distributed. Rotation is measured in square-pixel coordinates; translation is measured at the image centre. Degenerate or weak transforms stay unknown. Strong supported camera changes reject a pair. Face/body pose hashes and face SSIM are not vetoes.

Offline SFace and coarse apparel observations assist injective cohort matching. A shared companion cannot cover multiple observed people. Conflicting identity and independent apparel/pattern evidence can reject a replacement; missing or low-texture observations stay unknown. Known weak identity correspondence cannot be rescued by global colours alone. When camera geometry is unknown, a large coherent face-region scale change can identify different framing. This auxiliary guard uses independently detected, confidently matched face regions, never cached quality ROI size. The 1.7 framing ratio and appearance thresholds are experimental guards, not calibrated accuracy claims. Subject movement toward the camera, missed detections and perspective changes remain limitations.

No face identity names, enrollment or feature vectors are persisted. The existing local models and dependencies are reused. Technical quality assessment, ROI confirmation, paid-AI permission/protocol and manual selection implementations are unchanged. All input assets enter grouping; rejected/blurred assets are not removed from the universe.

The public portrait API uses this policy for both fresh and incremental grouping. The original build-15 engine is retained explicitly for landscape/compatibility; its function AST and 186 assertions in the migrated historical tests are unchanged. Historical global-transitivity and cross-date contracts do not describe the new burst policy. Public pixel-backed tests separately cover cancellation, publication rollback/resume, saved anchors, manual protection, decode failures, quality-state invariance and actual local blur. The Windows early-date timestamp defect was fixed in production; its original workflow membership assertions remain.

Portrait `standard` retains v9 at 12/90 seconds. `strict` only splits standard groups by an 8-second maximum gap and 60-second span. `loose` treats standard groups as atomic units, permits 18/120 seconds, and requires all cross-member pairs in both directions before merging. It never splits a standard group, and existing saved groups cannot merge with each other. Identity, camera, background, unknown-evidence and anti-bridge guards remain the same. Per-call loose-check contexts are cleared before return and are never persisted. Landscape preset semantics and the UI layout remain unchanged.

Validation distinguishes frozen real captures, synthetic timing, synthetic local blur and feature-structure fixtures. The 1000-photo partition and all-member contact sheets support inspection; group count does not measure accuracy. The 44-photo acceptance list exists only in the replay script, never production rules. Old 529 is a native historical-policy reproduction, not a recovered historical membership; Cullumi 392 is its saved normalized partition, not a controlled rescan.

Historical v9 report checks used file verification and DOM simulation, without a real browser or packaged-EXE claim. Build-16 delivery separately records new-source regression, exact full-member pre/post optimization comparisons for each preset, and native packaged-EXE acceptance. User photos, settings, the original workspace and frozen comparison evidence remain protected; opening an old workspace must not regroup it.

The final iteration also compares sufficiently large common-background layouts after removing a global exposure offset. A stable, confidently matched face scale keeps dynamic lighting inconclusive. The first corroborated multi-person reference may use strong identity support when camera geometry is unknown; it locks once and is never a rolling enrollment union. Partial reference coverage with an unknown camera requires strong identity and whole-cohort support. Reopening reconstructs the same bounded reference from saved members without moving the camera anchor or persisting vectors. These are experimental guards, not independent calibration.

The histogram optimization is limited to an ephemeral per-image uint8 HSV bin array shared by region histograms. Integer bins and normalized float32 histograms match frozen-v9 outputs exactly. There is no persistent cache, new parallelism, model change or reduced image resolution. Loose preset safety checks retain contexts only inside one grouping call; this separate preset feature has a memory/time cost reported for that preset. Inclusive profiler stages cannot be summed; histogram bin preparation must be included when comparing histogram cost. Serial wall-time measurements, CPU use and peak working set are recorded separately, with file-cache/thermal variability disclosed.
