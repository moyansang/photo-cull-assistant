# 清理证据图片（本地构建 3）

主页流程按钮下方新增“清理证据图片”。它只处理当前工作区 `focus-evidence/blobs` 内内容哈希匹配、CRC/图片校验通过的单图片 ZIP；混合包、未知文件、附带归档元数据和异常包保留。

点击后在后台只读统计并校验原片清单，再确认范围、数量、体积及风险。原片缺失或变化会显示数量和“可能无法重生成／与历史不一致”的警告，由用户决定继续；不会因此删除扫描记录。归档直接读取并校验其中的清单，不调用会同步删除缺图记录的扫描恢复函数。

按本项目清理约定，确认后先移入总目录 `待手动删除/<时间>-证据图片/<工作区>/focus-evidence/blobs`，校验并保存恢复清单。移出不等于释放磁盘空间；用户检查后手动删除，永久删除后无法从本功能恢复。其他安装布局默认使用程序上级的待手动删除目录，要求与工作区同盘。可按清单把未变化的 ZIP 移回原来的 blobs；不要覆盖同名不同内容。

保留扫描、评分选择、人工分组、裁切、AI 请求回答 JSON、任务、联系表、导出、普通预览及原尺寸临时缓存。主页显示已移出的历史图片数量；重新生成相同图片后不再计入缺失。清理不会触发扫描、联网评分或令已完成结果过期。

运行中/暂停处理任务、未保存回答的清晰度请求、路径不明、源与目标重叠、符号链接/目录联接、校验失败时拒绝。AI 清晰度调用与清理共享非阻塞进程锁；确认后重新校验，范围变化则重新统计。部分文件占用时保留失败文件并报告；中断前已写恢复映射，已移动文件留在待手动删除目录。

原片完整且未变时，后续“AI 选片与导出 → 开始 / 继续未完成批次”沿用任务联系表；缺失联系表可由现有分析和原片重建，不需要因证据清理重扫。新清晰度复核从现有原尺寸缓存或原片生成图片，不依赖历史证据 ZIP。原片缺失/变化仍受原有来源校验约束。重新联网提交可能产生 API 费用。

“重新提交”仍保留既有重置当前评分、人工确认、历史和旧任务的行为；它不是重试失败批次。构建 3 未改变原片增删同步策略；构建 4 的证据同步补充如下。


## 原片同步补充（本地构建 4）

新增照片仍先提示，点击“扫描图片”后增量处理；证据在需要清晰度请求时生成。普通恢复不会为新增照片提前生成证据。原片修改、重命名沿既有规则；重命名按旧文件减少、新文件增加处理，整目录离线保留原记录。

既有恢复流程剔除缺失原片记录前，先核对证据引用；只有属于被删除照片且没有其他存活或未知请求引用的纯图片包才移入待手动删除。请求/回答 JSON 不删除、不重写，清理清单标记历史图片已整理。未变化照片的证据保留。

新请求增加原片归属字段；旧请求从扫描及 AI 照片记录内的 audit 引用识别。source-removals.json 保存已确认删除的归属，以便跨多次删除判断共享图片最后一个引用。无法证明归属、原片位置不一致或异常状态时保守保留；不通过提示词或文件名猜测。历史上已失去引用的旧请求可能需要使用手动清理按钮。

同步与 AI 调用、手动清理共用锁。运行或暂停任务、未完成请求、路径逃逸均阻止整理；移动失败保留扫描记录供重试。仅调用既有恢复流程才执行同步，手动按钮仍允许原片缺失经警告确认继续。移动可恢复、不代表释放空间。

本次不迁移证据格式。像素等价不等于文件字节或 SHA-256 相同；以后若采用无损重编码，需要保留原请求哈希与新存储内容的对应关系，兼容历史请求溯源。
