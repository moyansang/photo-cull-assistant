# 清理证据图片（本地构建 6）

主页“清理证据图片”只处理当前工作区 `focus-evidence/blobs` 中内容哈希、CRC 和图片校验通过的单图片 ZIP。混合元数据包、异常包、未知文件、带附加归档元数据的包以及硬链接保留。

## 手动按钮：确认后永久删除

点击按钮先后台只读统计，再显示工作区、数量、体积、原片缺失/变化数量和风险。默认选择“不”。只有用户再次明确确认，才永久删除本次范围内的证据图片；不移入回收站或“待手动删除”，删除成功后释放对应图片文件空间，无法由本功能恢复。

原片缺失不硬阻止，确认框说明缺失原片无法用于重建；即使原片仍在，重新生成也不保证与历史图片完全相同。内容去重的共享图片只删除一次，但所有引用它的历史请求都会失去图片；请求与回答文本保留。此按钮针对当前工作区全部已确认图片范围，不把共享引用误计为多个文件。

不修改扫描记录、评分选择、人工分组、裁切设置、AI 请求回答 JSON、任务、联系表、导出、普通预览和原尺寸临时缓存，不重新扫描或联网评分。归档工作区在原地只读校验，归档内容保持不变，不调用会剔除缺图记录的恢复流程。

运行中/暂停任务、未保存回答的请求、路径不明、符号链接或目录联接等状态拒绝删除。手动删除与 AI 清晰度调用、自动整理共用证据锁；确认后重新检查范围和状态。每个文件删除前复核哈希及硬链接数。文件占用或发生变化时保留失败项，报告实际成功数量、文件体积和失败原因。

删除前在 `focus-evidence/evidence-cleanup.json` 保存 `permanent_delete` 操作意图、文件清单及哈希，正常结束补充结果。中断时也能解释哪些历史图片已经缺失。此记录不是备份。主页仍显示历史证据图片已清理状态；重新生成相同图片后不再计入缺失。

## 原片同步：删除原片后同步永久删除独占证据

用户明确选择：原片删除后，重新打开工作区按既有规则移除缺图记录，并同步永久删除仅属于这些照片、没有存活或未知请求引用的纯图片证据。不会再移入待手动删除，不进入回收站。其他照片的结果和证据、所有请求回答文本保持不变。

新请求记录 `source_paths`；旧请求从扫描及 AI 照片记录的 `audit` 引用识别归属。`source-removals.json` 保存已确认删除的归属，以便跨多次删除判断共享图片最后一个引用。无法证明归属、位置不一致或异常状态时保守保留，不通过提示词或文件名猜测。

同步复用证据锁、完整状态重验和逐文件哈希/路径校验，仅删除经筛选的独占图片。操作意图和结果使用 `source_sync_permanent_delete` 标记；请求回答保留。部分删除失败时保留原扫描记录供下次打开重试；成功删除的图片由清理记录解释，重试只处理仍存在的符合条件图片，不伪称失败文件已删除。

整个原片根目录/磁盘不可达、原片读取错误、活动或暂停任务、未完成请求、未知归属、路径联接或逃逸均不会触发自动删除。新增照片仍先提示，点击“扫描图片”后增量处理，证据在需要清晰度请求时生成。修改需按既有规则重扫；改名按旧文件减少、新文件增加处理，不另改扫描流程。

## 格式与后续任务

没有实施额外压缩或格式迁移，构建 7 另已取消关闭与切换时自动归档，保留旧归档读取恢复兼容。后续任务仍按原有来源校验执行；缺少历史证据不自动要求重扫或令已完成结果过期。像素等价不等于文件字节或 SHA-256 相同，未来格式迁移须单独设计请求溯源兼容。

“重新提交”仍是既有重置评分、人工确认、历史及旧任务的行为，不是重试失败批次。新联网提交可能产生 API 费用。
