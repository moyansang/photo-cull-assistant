# 裁切拆组与风景建议宽松：原因定位和候选实验

日期：2026-10-14。代码基线 `52bd1b4e70db93a2c39e521ba1b8b37370ab0fa3`。

## 已定位的原因与仍缺证据

1. **裁切拆组主要卡在未对齐的灰度结构比较，不是只差一个dHash阈值。** 14张已取得原图四边各裁5%后，14/14的结构值低于0.78，范围0.221–0.652；7/14其实已经通过dHash≤10。宽高比14/14通过。单独把dHash放宽到20，对整个84对测试零改善。
2. **风景特征确实会将随机噪声当成清晰细节。** 给固定模糊图加入不恢复原始景物细节的Gaussian随机噪声，可以把review提升为keep；两种输入、5个种子重复确认。这比“人类锐度低却keep”更能定位算法风险，不需要把人类Sharpness擅自变成弃置标签。
3. **尺度也会改变判定，缩图不是可靠修复。** 9张SPAQ图缩到宽高各1/4后全部keep，原来的唯一review也转keep。补做了相同中心区域缩放与原生完整分块对照，避免把像素尺度和取样覆盖混为同一原因。
4. 以上行为与当前公式、阈值和“至少2块clear即keep”一致；在所查路径未发现实现结果偏离这些规则。不能由此声称全系统无实现错误。风景自动reject仍没有经过可靠标注校准，本轮没有增加reject分支。

尚缺：人工技术K/D/U、真实连拍比较组、场景独立划分、自然裁切/旋转/平移困难负对和未见验收集。当前14个来源ID不一定代表14个独立场景。**本轮输出是原因定位和开发候选，不是产品准确率或已完成阈值校准。**

## 实验范围与可复现性

只用已经取得的5张KonIQ景观和9张官方Landscape标签SPAQ图，无新增下载、网络AI或用户照片。保持原图字节不变，变体只存在内存中。

真实调用生产的`landscape_evidence`、`_region_metrics`、`_visual_from_image`、`grayscale_structure_similarity`。裁切pair实验不改工作区、不改变手工/AI决定或固定代表。另以生产`_similar`逐一核验84个基线pair，所有布尔结果及结构值与实验记录相符。候选比较只是离线pair判定，**未接入生产分组检索、缓存或增量分组**。

当前三个算法文件与前次`fe0aaf3e`版本相同（相关git diff为空），因此不是UI提交改变了算法结果。输入/源码/脚本SHA256及代码版本记录于`results/version.json`和`results/verification.json`。

## 一、裁切与结构对齐

### 测试设计

每张原图生成四边各裁1%、2%、3%、5%、7%、10%的版本，14×6=84个同来源pair。分别比较：

- 生产standard基线：dHash≤10、block SSIM≥0.78、宽高比≤1.15。
- 只放宽hash：dHash≤20，结构仍≥0.78。
- 同时放宽：dHash≤20、结构≥0.50。仅作预先固定的宽松诊断，不搜索最佳阈值。
- 中心裁切特征库：给代表图计算0%、2.5%、5%、10%四种中心裁切的特征；任一变体仍满足standard的原阈值才通过。

不同来源代理pair包括14张原图全量91对，加每张原图对其余13来源的6种裁切，共1,183对。不同来源并非人工认定的不同组选片真值；同来源也不必然应属于同个人工比较组。

### 实测

|候选|84个同来源pair匹配|1,183个不同来源代理pair匹配|
|---|---:|---:|
|standard|21|0|
|只放宽hash到20|21|0|
|hash20 + structure0.50|53|0|
|4档中心裁切特征库|73|0|

逐裁切比例匹配数（每列分母14）：

|候选|1%|2%|3%|5%|7%|10%|
|---|---:|---:|---:|---:|---:|---:|
|standard|13|7|1|0|0|0|
|只放宽hash|13|7|1|0|0|0|
|hash20+structure0.50|14|13|12|8|5|1|
|中心裁切库|13|14|14|14|4|14|

5%和10%恰好在候选特征库网格内，完全恢复是预期的合成对齐效果，不能算泛化胜利。未落入网格的1%、2%、3%、7%合计56对中，基线21对、裁切库45对；7%仍仅4/14匹配。这说明对齐方向有价值，也说明固定少量网格并不能解决任意裁切。

原始5%失败例：田野`koniq_169779095.jpg`的hash距离9，结构0.636；游乐园`koniq_196734006.jpg`的hash距离4，结构0.484。即使候选已被hash找出，未对齐的对应块结构仍会拒绝。14张5%裁切的最高结构0.652，低于loose预设0.68，因此单纯切换现有宽松预设也解决不了本批问题。

### 候选和代价

**更值得继续研究：保留原standard阈值，增加受限裁切对齐候选；不建议直接把全局结构阈值降到0.50。** 本批宽松阈值没有跨来源匹配不等于安全，只有14个原始来源，重复衍生pair高度相关。需要同色调/重复纹理/低纹理自然负对才能估计污染组风险。

四档特征提取在本机14图共约2.51秒，对单档约0.66秒，为3.8倍（首次重复约3.5倍）；这是特征提取环节，不能冒充整个扫描耗时倍数。派生描述子和索引键最多约4倍，候选每pair最多4次结构验证，还可能扩张BK-tree候选集合。当前实验未测整库吞吐或内存峰值。

10%四边裁切只保留64%画面面积，可能丢掉改变拍摄意义的边缘内容。实现前须限制匹配覆盖、保留原图代表身份、手工组保护和增量稳定性，并测不对称裁切/平移/旋转；不能拿这个pair脚本直接替换生产分组。

## 二、评分：阈值、噪声、尺度和取样覆盖

### 生产规则与采样

风景把图像切为4×4格，每格仅取原生中心最多384×384像素，调用原来用于身体区域的纹理指标。单块clear要求归一化fine Laplacian≥0.0038、coarse Laplacian≥0.00072、curvature≥0.16，并先通过对比/纹理门控。整图只要2块clear就keep。没有人工标注主要景物，也不要求整图都清晰。

SPAQ9图原生采样覆盖约18.2%–48.0%像素。它的优点是保留原生细节尺度和有限内存，但不能代表主要景物一定被采到。`keep`也不等于整体质量高、低噪声或高审美。

### 加噪反事实：可复现的升级问题

使用SPAQ `08862.jpg`原图，以及KonIQ田野已保存的Gaussian blur3变体。仅加零均值独立RGB Gaussian噪声，8位像素标准差为4、8、16；种子20261014–20261018。变体不继承原图人工分数。

|输入|噪声σ|原规则keep次数/5|
|---|---:|---:|
|SPAQ08862|0|0/5|
|SPAQ08862|4|0/5|
|SPAQ08862|8|5/5|
|SPAQ08862|16|5/5|
|田野blur3|0|0/5|
|田野blur3|4|5/5|
|田野blur3|8|5/5|
|田野blur3|16|5/5|

种子20261014时，田野blur3在σ4时clear块数0→9；SPAQ08862在σ8时1→2。原始景物细节没有被恢复，随机高频成分却满足了现有清晰块条件。五个种子不是五个独立真实场景，这里只证明这两个反事实例可稳定复现。

### 候选未达到可直接落地标准

A. 提高整图clear块门槛：SPAQ9图把2改为4时keep8→7，改为8时8→6；最低Sharpness四分位4图的keep3→2→1。但`09114.jpg`仍有12块clear，不能解决所有低锐度风险。田野加噪例有9–11块clear，门槛8仍会放行。构造的“两块真实高频细节+平坦背景”控制图则从keep变review，增加低纹理/局部清晰场景的人工负担。

B. 额外Gaussian预平滑：sigma0.5没有阻止初始加噪例；sigma1在部分噪声强度有效，但SPAQσ16和田野σ16仍5/5 keep。简单预平滑也没有改变9张真实SPAQ的8keep/1review分布。不能把一次模糊滤波当成噪声鲁棒性修复。

C. 粗细尺度细节比：开发性筛选只让coarse/fine Laplacian比值≥阈值的clear块参与整图keep，仍只输出keep/review，绝不因此reject。阈值0.05/0.10/0.20是在看到诊断后作的敏感性试验，**不是冻结校准阈值**。

|比例门槛|14张原图keep/review|原规则已被加噪提升的25个重复例仍keep|
|---|---|---:|
|无新增门槛|13/1|25/25|
|≥0.05|11/3|10/25|
|≥0.10|10/4|5/25|
|≥0.20|4/10|0/25|

门槛0.20虽然挡住这些加噪例，也把SPAQ人工Sharpness81.33、75.27的两张图转review；0.10还把KonIQ田野（整体人工ACR约3.49/5）转review。两块细节的合成控制图在0.10和0.20也被转review。这是明确代价，不能只展示噪声改进。比例对正常细碎纹理也敏感，并非可靠的噪声探测器。

**建议研究方向：噪声/锐化与真实空间结构的一致性证据，先作为“降为待复核”候选，并加入天然细纹理与低纹理控制。** 当前任何单一候选都不足以打开自动弃置；不推荐仅为使这14张好看而硬改阈值。

### 像素尺度与采样覆盖分开检查

- 整图缩到1/2：仍8keep/1review；缩到1/4：9keep，SPAQ08862从1块clear变3块clear。缩图同时改变取样面积与像素尺度，不能单凭这个结果判断具体是哪一个因素。
- 固定原生分块区域、改为测每格全部像素：仍8keep/1review。例如09114的clear12→9，00825的3→2，都仍keep。单独扩大覆盖没有解决本批宽松输出。
- 固定每个原生384中心区的场景范围，仅把该区缩到1/2再调用同一指标：00825从3块clear变1块并review，其他总体结果不变。证明像素尺度自身会改变规则响应。
- 原生中心区的重放逐块state与生产输出全部一致，因此对照不是误写了一个不同的基线。

由此不建议用“统一缩略图尺度”直接替代现有原生证据。若研究多尺度，应并列保留原生与尺度来源、避免缩图把模糊升级，且不能把变体继续套用原图Sharpness当新人工标签。

## 三、指标含义与下一阶段边界

- 裁切pair的分母84是14个来源的合成变体，不是84张独立自然照片；1,183个负代理pair也只有14个原始来源，零匹配不能证明污染风险为零。
- 不将“同来源匹配率”称为人工分组准确率。pair脚本没有验证生产簇的固定代表、传递性、人工组保护或大规模索引性能。
- SPAQ人类Sharpness用于定位低锐度分层；没有用户用途与K/D/U，不能计算坏片漏检、误弃或弃置精确率。
- 随机加噪实验能说明特征响应机制，但不证明本批真实低锐度图就是由噪声引起，也不取代真实标注。
- 没有把候选最好的一档称为通过验收。全部调研样本已经被查看，后续只作为开发/回归资料，新验收需要未见场景族。

推荐下一步的次序：

1. 裁切：在评估分支保留原阈值试验受限对齐，新增不对称裁切、构图近似不同景物、不同主体但重复背景的人工pair；同时量化索引成本。
2. 风景：先将可复现的噪声升级与缩图升级作为开发回归案例，验证候选不会将证据不足图升级为明确清晰。
3. 收集真实用途和意图明确的K/D/U，双人标注、按场景族隔离。只有同时满足安全和覆盖指标，才研究自动reject。

```

```

KonIQ目录需保留前阶段的`images/`、`scene_selection.json`以及已生成的田野`variants/169779095__blur3.jpg`；SPAQ目录需`images/`和`annotations.json`。素材来源/许可见前两阶段报告，不重复分发图片。

`results/grouping-attribution.json`含每个pair的hash/结构/宽高比及候选计数；`landscape-attribution.json`含45个尺度/预滤波记录和全部分块指标；`detail-persistence.json`含14原图、40个含无噪声对照的重复记录；`coverage-scale.json`含9图解耦对照；`verification.json`保存84个生产判定核验和脚本哈希。

结项范围：本次原因定位和离线候选实验完成。生产评分/分组未修改、未推送；真实准确率与可靠自动弃置仍不能判定完成。
