# AI选片助手 v1.2.1

Windows 便携选片工具：本地扫描照片、分组、生成联系表、修正人脸小窗；通过 Lightroom Classic 插件把评级和弃置状态写入 Catalog。

## 使用流程

1. 解压完整便携包，运行 `AI选片助手.exe`，选择照片文件夹和工作区。
2. 点击“扫描图片”，只做本地人脸检测、虚焦／抖动初筛和初始分组，不调用 API，不生成联系表。
3. 编辑选片组并检测／调整人脸框。人脸窗口的“重新扫描修改过的图片”仅重做修改照片的本地筛查，保留手动分组。
4. 按需点击“AI 复核”，检查清晰度待确认照片；明确模糊的直接标记弃置。然后点击“生成联系表”，再进入“AI 选片与导出”。没有 API 时跳过复核，后续仍可使用网页提交。联系表未变时恢复已有任务和结果；初筛弃置照片不进入正式 AI 选片。
5. 网页选片：合并所选批次，复制一份提示词，上传对应图片，再粘贴完整 JSON 回答。API 选片：选择配置并开始；修改偏好后使用“重新提交”重新准备全部合格照片并提交。
6. 在“选片结果”表查看对应照片、AI 理由、星级和弃置状态，点选照片可看预览与完整说明。
7. 点击右下角“导出到 LR”，将 AI 星级／弃置建议和初筛弃置合并为 `lightroom_results.json`；在 Lightroom Classic 插件中导入后查看原图复核。全部照片保留原目录。

## v1.2 分阶段处理与工作区整理

主页面按钮分四行：

- 扫描图片、编辑选片组、检测/调整人脸框。
- AI 复核、生成联系表、AI 选片与导出。
- 停止处理、继续处理、打开联系表目录、清空工作区。
- LR 插件、检查更新、不再自动检查更新。

扫描只做本地检测、技术初筛和分组。人脸修改后只重新扫描修改照片，保留人工分组。AI 复核只处理有可靠人脸的待确认照片；没有可靠人脸时跳过请求并提示先调整。已有有效复核结果复用。生成联系表不再触发本地筛查或 API 复核。停止/继续按原阶段恢复，已完成单元不重复处理。

“清空工作区”确认后移除当前工作区内全部数据，重置该工作区设置，保留工作区文件夹及全局 API 配置。与原片目录重叠、包含程序文件的工作区禁止清空。

完成当前 AI 选片并导出后，关闭或切换工作区会自动整理：校验归档后清理可重建预览与分析缓存，项目 JSON 和日志压缩保存；联系表、AI 提交材料及工作区中的 LR 导出结果不压缩。未完成、已过时或尚未导出当前结果的工作区不整理。再次选择时自动恢复项目状态，预览按需从原片重建，不重新请求 AI。原片发生变化或缺失时会提示，不覆盖已有结果。下文历史版本段落描述其当时行为，以本节和当前使用流程为准。

## API 模型预设

打开“配置 API”，选择预设、填写对应平台 API Key，测试并保存即可。高级设置可展开修改名称、地址、模型和超时等；也可选择“自定义”。原有配置保留。

| 预设 | 模型编号 | 默认接口前缀 |
|---|---|---|
| 阿里百炼·北京 / Qwen3-VL-Plus | `qwen3-vl-plus` | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 阿里百炼·北京 / Qwen3-VL-Flash | `qwen3-vl-flash` | 同上 |
| 智谱 / GLM-4.6V-Flash | `glm-4.6v-flash` | `https://open.bigmodel.cn/api/paas/v4` |
| OpenAI / GPT-5.4 mini | `gpt-5.4-mini` | `https://api.openai.com/v1` |
| DeepSeek / Flash（支持图片） | `deepseek-flash` | `https://api.deepseek.com` |

- 预设仅填写接口参数；账户需具备服务权限及可用额度。百炼预设使用北京地域公共域名（官方仍支持），必须搭配北京地域 Key。其他地域/业务空间专属域名请用自定义。
- 首次保存千问某一型号后，另一个型号在密钥留空时可复用同地域已保存的 Key。不会跨服务商复用；修改服务地址需重新输入密钥。
- GPT 预设自动使用 `max_completion_tokens`；Qwen 和 DeepSeek 预设关闭思考模式，GPT 使用 `reasoning_effort=none`。默认超时 300 秒，输出上限 8192 tokens。GLM 使用服务默认思考设置。
- DeepSeek 预设使用官方当前支持图片的 `deepseek-flash`；旧实验视觉模型已由新 Flash 承接。单请求编码后不超过 48 MiB，超限提示拆小批次。
- 修改预设的地址或模型后按自定义配置保存，不再套用原预设专用参数。
- 2026-09-11 核实的官方资料：[百炼视觉](https://help.aliyun.com/zh/model-studio/vision)、[百炼地域与域名](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[智谱视觉](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.6v-flash)、[OpenAI GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)、[DeepSeek 视觉](https://api-docs.deepseek.com/zh-cn/guides/vision/)。

## AI 任务与 API

- AI 星级和弃置建议独立记录，低星级不自动等于弃置；导出合并当前 AI 建议与初筛技术弃置。
- 回答严格校验任务、批次和照片唯一编号。重复、未知、缺失、错误类型均显示异常；有效部分保留，原始回答也保存。兼容严格的“文件名,星级”简化输入，同名歧义拒绝导入。
- 主页联系表内容改变后才自动新建全量任务；未变化时保留任务、评分和提交进度。主动“重新提交”会按当前偏好替换上一轮结果。
- 默认批次尽量保持完整组，约 24 张照片；超大组独立一批。“拆小本批重试”创建更小的新任务，可能拆组，提示词会注明比较范围。
- 分组成员、照片文件或裁切改变会使相关组结果过时；旧快照不能继续提交或套用回答。
- 主页面的已完成扫描、分组、日志及偏好会记忆；再次进入 AI 选片窗口会保留原任务，主页联系表内容变化后才自动准备新一轮，已导出的 LR 文件仅在再次导出时替换。
- **当前 API 协议仅支持带图片的 OpenAI-compatible Chat Completions**。接口地址支持前缀（如 `https://服务域名/v1`）或完整 `/chat/completions` 地址；不代表支持所有模型厂商的原生协议。
- API 普通配置位于设置目录的 `ai-api-profiles.json`；密钥单独存入当前 Windows 用户的凭据管理器，不写入项目 JSON。复制便携包到另一用户/电脑需要重新输入密钥。
- “测试连接”发送合成的 1×1 图片，不发送用户照片。实际提交仅发送所选批次提示词和联系表；原片绝对路径留在本地。服务方可能对测试和评审计费。
- 单请求上限：20 张联系表、每图 20 MiB、总图 48 MiB。默认超时 120 秒，可配置；超时不能证明服务方未处理，请按需重试。
- 本地模拟网络、Windows 凭据读写和 EXE 流程均有验证；未使用真实付费模型验证选片质量。

## Lightroom 插件

完整便携包包含 `lightroom/PhotoCullAssistant.lrplugin` 和中文安装说明。

在 **Lightroom Classic → 文件 → 增效工具管理器 → 添加** 选择整个 `.lrplugin` 文件夹，启用后使用图库模块菜单 **文件 → 增效工具附加功能 → 导入 AI选片助手结果**。

- 使用完整原片路径匹配当前目录；不按文件名猜测，不处理虚拟副本。
- RAW、JPEG 分别匹配；没有作为独立照片导入的 JPEG 会报告未匹配。
- 只修改结果显式指定的 `rating` 和 `pickStatus`，不改调色、标题等元数据。
- 普通低星级不是弃置；评级与旗标独立。
- 人工只填星级时保持原旗标；需要撤销弃置请显式选择“无标记”。
- 按完整路径匹配后应用结果，找不到的路径跳过；不再保存不可见的旧导入报告。
- 不执行图片导入、照片移动、删除或 XMP 操作，不直接编辑 `.lrcat` 文件。
- **如需照片目录没有 XMP，请关闭 LR 的“目录设置 → 元数据 → 自动将更改写入 XMP”。** Lightroom 自身或其他工具仍可能创建 XMP。
- 旧版已有 XMP 保留，不删除；新版本不再写入或依赖它们。
- 当前测试覆盖导出流程及 Lua 5.1 模拟目录调用；真实 Lightroom 菜单与目录写入需要宿主验证。

## 照片、分组与人脸细节

支持常见图片及 RAW 预览，RAW+JPEG 视为逻辑照片。按拍摄时间和画面变化分组，严格/标准/宽松可选；支持人工拆组、合组，工作区 groups.json 保存分组。重新自动分组会覆盖人工分组。

人脸小窗使用离线 YuNet；优先置信度，结合主体位置。背景图案、侧脸和遮挡仍可能导致误检或漏检：

- 点击蓝色候选框选脸，拖框补选漏检的人脸。
- 拖动预览中的绿色裁切框调整位置，用鼠标滚轮调整裁切范围；裁切比例仍可选择，调整逐张保存。开启“手动选人脸”后可重新框选人脸。
- 置信度全局生效；手动框不受阈值影响。
- “下一张未标记”循环查找待补选照片，跳过已手动隐藏的小窗。
- 可隐藏本张小窗、恢复自动选脸；点击保存后重新生成联系表，取消则放弃本次修改。
- 修改按原照片绝对路径关联，移动原照片后需重新设置。

技术筛选只建议弃置明显人物主体虚焦/严重抖动，不能可靠确定主体时保守保留。建议查看 `contact_sheets/rejected_review` 后人工确认是否弃置。

## 目录与设置记忆

便携版将全局设置保存到 EXE 同级的 `settings/`，每批照片默认使用 `workspaces/照片文件夹名-唯一编号/`。API 服务及更新开关全局记忆；分组、每页照片数、列数、技术筛选和人脸设置保存在各工作区的 `workspace-settings.json`。切换照片文件夹自动恢复关联工作区，也可以指定自己的工作区。源码运行的数据位于 `%LOCALAPPDATA%/AIPhotoCullAssistant/development/仓库编号/`，不再写入仓库根目录。

工作区主要输出：

- `previews/`：预览图。
- `contact_sheets/main/`：主联系表。
- `contact_sheets/rejected_review/`：疑似技术问题照片。
- `groups.json`：分组。
- `screening_results.json`：技术筛选详情。
- `ai_project.json`：任务、AI 回答、人工决定和应用状态。
- `ai_tasks/`：每次任务的联系表快照与提示词。
- `lightroom_results.json`：最近一次导出的 LR 结果；重新导出会替换，扫描不替换。

## 开发与打包

Python 3.12 推荐。安装 `pip install -e ".[raw,dev]"`，运行 `python -m pytest -q`。测试包含 Lua 5.1 插件模拟宿主验证（lupa，仅测试依赖，不随 EXE 打包）。

运行 `build_exe.ps1` 构建包含 LR 插件的便携目录，运行 `make_portable_zip.ps1` 生成 ZIP。

SDK 参考： https://developer.adobe.com/lightroom-classic 及 Adobe SDK 文档镜像 https://lrc.mcor.dev/ 。json.lua 来源及 MIT 许可见 `lightroom/安装与使用.txt` 与库文件头。


## 自动更新
启动 EXE 后后台检查 GitHub 正式版。发现新版可选择下载更新；“不再自动检查更新”会记忆，手动“检查更新”仍可使用。
下载核对 GitHub SHA256，解压后按程序文件清单校验；退出当前 EXE 后只替换清单内程序文件并重启。设置、工作区、照片和用户新增文件不在替换范围内；同名程序文件被用户修改时中止更新。复制失败尝试恢复备份，不删除整个安装目录。
临时下载、旧程序备份与错误日志位于 Windows 临时目录 photo-cull-update-* 下。
v0.4.8 及更早版本没有更新器，首次需手动升级到 v0.4.9 或更新版本；此后可通过程序更新。

选片仅改变 Lightroom 中的星级与标记：不复制、移动或删除原照片。旧版生成的精选文件夹不会自动清理。

更新接口遇到 GitHub 限流或网络错误时，自动尝试 Releases 的 update.json 备用通道。成功检查缓存 6 小时；手动检查始终重新查询。发布新版本时须将 make_portable_zip.ps1 生成的 update.json 与 ZIP 一起上传。


### 网页合并提交

AI 选片窗口分为 **API 选片、网页选片、选片结果** 三页。进入时自动准备本轮任务，API 和网页页共用选片偏好。
网页提交支持 Ctrl / Shift 多选批次，或一键全选未完成批次，点击“合并准备所选批次”即可复制一份完整提示词并打开全部联系表目录。
在大模型网页一次上传目录中的联系表并粘贴提示词，收到回答后使用“导入整份回答”，自动分配回各批次，再到选片结果查看。
合并提交历史会保存，可继续复制提示词、打开图片及导入回答；照片分组不变，原照片不移动。
如果网页的图片数量或回答长度限制不允许一次全部处理，可以减少所选批次，分几次合并提交。提示词始终完整，不拆分固定规则。
缺失、重复或不匹配的回答会保存原文并提示修正，不会部分覆盖照片结果；修改照片或裁切后需重新创建任务。


### 关闭后继续选片
完成扫描后，工作区自动保存 scan-session.json 与 session.log。重新打开同一照片目录和工作区，恢复预览路径、分组、技术筛选与人脸分析，可直接进入 AI 选片继续原任务。人脸和分组编辑也会保存。原片发生修改或丢失时提示重新扫描；新增照片需主动扫描。旧版本没有扫描快照，升级后需完成一次扫描以建立记录。


### v0.5.9：在 Lightroom 复核
AI 窗口仅显示 API 提交、网页提交。选片完成后点击底部“导出评分与弃置到 LR”，在 Lightroom 插件中导入 lightroom_results.json 应用星级与弃置标记。无需在软件逐张确认。已有人工确认结果优先；不自动清除没有弃置建议照片的 LR 原旗标。


### v0.5.9：处理进度与续做
扫描和重新生成联系表显示估算总百分比，共用停止／继续。完成当前处理单元后停止，已完成照片和页面保存，重启后可继续。
续做时已完成部分保持原设置，后续工作使用当前设置；分组作为完整阶段执行，完成的分组不因续做重做。新增照片留到下次扫描。原照片改动或丢失只清除本次中断任务。
修改灵敏度后在人脸窗口点击“保存并重新生成联系表”应用重新分组；仅更改每页数量和列数保留分组。人工分组被覆盖前会提示。
“清空日志”清除磁盘历史日志，新的运行消息继续记录。“推荐下一步”替代旧流程说明。

### v0.5.6 人脸清晰度筛查

- 技术筛查与联系表共用 YuNet 人脸位置，并尊重手动人脸框。
- RAW 使用完整解码的人脸细节评估，避免缩略预览掩盖抖动；低分辨率、低对比度、噪声及边界情况不自动弃置。
- 重新生成联系表会更新技术筛查；原片、脸框和算法未变化时复用工作区分析缓存，支持停止后继续。
- 已有工作区升级后，启用技术筛查并在人脸窗口点击“保存并重新生成联系表”应用新规则；结果仍统一导出到 LR。

阈值使用本地 126 张 RAW 检查分布与边界，其中 4 张有用户确认标签，新规则在这 4 张上符合标注。这是小样本校准，并不代表对所有人物、遮挡及拍摄条件都有同样准确率。未可靠检测到人脸时不作自动弃置判断。原片始终不移动、不修改。

### v0.5.10 模糊漏检修正

修正高对比度软边缘导致模糊照片停留在“不确定”的问题：联合细节量、边缘锐利程度和较粗尺度细节进行判断，不再让梯度强度单独阻止弃置。保留低分辨率、低对比度和噪声保护。

以用户标注的 8 张模糊、3 张清晰 RAW 做本地校准回放，均符合标注；同一文件夹的 126 张照片用于观察规则影响，其中 117 张检测到可分析人脸。候选规则使其中 20 张由不确定改为模糊（包含本次 5 张漏检样本）；未标注照片不作为准确率真值，11 张也是校准集而非独立测试集。

升级后在“检查／调整人脸框”点击“保存并重新生成联系表”应用新规则。算法缓存版本已更新，旧判断不会被直接复用。

### v0.5.11 API 配置窗口切换修复

API 配置使用不独占输入的所属窗口；切换其他程序后选片页仍可操作，再点配置 API 可恢复原窗口及未保存输入。关闭时清理轮询并恢复父窗口状态。

### 本地改进：LR 清晰度待确认标记

统一导出新增可选布尔字段 `focus_review`。技术检查不确定、无法检测或无法可靠分析人脸时为 true；明确清楚或技术弃置时为 false；未执行筛查时省略，保持 LR 既有标记。待确认状态可以单独导出，不要求先得到 AI 星级。

更新随代码提供的 LR 插件并重载后，导入结果会同步 `AI选片_清晰度待确认` 关键词，并自动建立同名智能收藏夹。复核后移除关键词即可离开收藏夹。关键词与星级、弃置独立，其他关键词不受影响。旧格式导入不会清除该标记。再次导入旧的待确认结果会重新添加它。

本改进仅建立本地筛查状态到 LR 的同步通路，不包含 AI 二次判断。


### 清晰度复查与选片方式

主页面的 API 配置由“AI 复核”和 API 选片共用。扫描图片和生成联系表均不会调用 API。

- **API 复查 + 网页选片**：扫描图片 → 调整分组与人脸 → AI 复核 → 生成联系表 → AI 选片与导出 → 网页提交 → 上传图片与完整提示词 → 粘贴回答 → 导出到 LR。无需删除或关闭 API 配置。
- **全 API**：扫描和人脸调整完成后点击 AI 复核，生成联系表后在 API 选片页开始提交。
- **全网页**：不启用 API，网页提交材料会为尚未复查的待确认照片加入原生像素细节图，交给模型一并判断。

AI 明确判断模糊时直接标记弃置，并在日志中统计数量；不会删除或移动原片。仍无法判断的照片保留“清晰度待确认”，导入 Lightroom 时使用同名关键词。已有 API 复查结果会沿用到网页提交，不重复复查。单张 AI 清晰度复核失败时会记录错误并继续其他照片；本轮结束后可选择仅重试出错照片，或跳过并保留“清晰度待确认”。出错记录和处理进度会保存，已成功的照片不会随重试重复请求。


### 在 Lightroom 查看 AI 判断理由

更新插件并重新加载后，在 EXE 重新导出选片结果，再通过 Lightroom 插件导入。进入图库模块，选中照片，在右侧“元数据”面板顶部的下拉菜单选择“AI选片助手”。可查看 AI 选片理由、清晰度结论、清晰度核查理由和待确认事项。

文字保存在插件专用的目录元数据中，不覆盖原照片标题或说明，插件不将这些文字写入 XMP。旧结果文件仍可导入，未携带的文字字段保持原值；新结果中的空字符串会清除对应旧文字。过时的选片回复不会作为当前回复导出。不需要为了补充这些字段再次调用 AI，重新导出已有有效结果即可。


### 新工作区内部结构与迁移

- `previews/`：预览图；`contact_sheets/`：联系表；`ai_tasks/`：提交材料和回答。
- `exports/lightroom_results.json`：导入 Lightroom 的结果。
- `logs/session.log`：日志；`cache/analysis/`：分析缓存；`cache/processing/`：中断任务。
- 根目录的 JSON 文件保存项目和扫描状态。

首次使用新目录规则时，旧设置和仓库／EXE 根目录中的工作区数据会复制到新位置，并更新生成文件的路径引用。原件保留，不复制原照片、不改凭据标识。目标已有其他内容时停止迁移，避免覆盖。自选工作区保持原位置；已有旧布局继续兼容，新的工作区使用上述结构。迁移完成后不会反复覆盖新设置。更新器仍只更新程序清单中的文件，设置和工作区不属于更新目标。
